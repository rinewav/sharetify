# iPhone 実機での確認手順

このプロジェクトの最大の未検証事項は「iOS の PWA で、画面をロックしたまま音が鳴り続けるか」。
ここが成立しないと構成そのものを見直すことになるので、まずこれを確かめる。

---

## 1. サーバーを起動する

```bash
# 自分の PC の node サーバー (音声の取得を担う)
pnpm --filter @musicshare/desktop dev

# 画面
MUSICSHARE_PUBLIC_HOST=my-macbook-pro.tail17329a.ts.net pnpm dev:web
```

`MUSICSHARE_PUBLIC_HOST` は更新通知 (HMR) の接続先を実機向けに変えるためのもの。
省略しても再生の確認はできる（更新が自動反映されなくなるだけ）。

## 2. Tailscale で公開する

```bash
tailscale serve --bg --https=8443 http://127.0.0.1:5273
```

443 は別の用途で埋まっているので 8443 を使っている。
確認:

```bash
tailscale serve status
```

止めるとき:

```bash
tailscale serve --https=8443 off
```

## 3. iPhone から開く

同じ tailnet に iPhone が参加している状態で、Safari から:

```
https://my-macbook-pro.tail17329a.ts.net:8443/
```

Tailscale が正規の証明書を出すので、**HTTPS として扱われる**。
これが重要で、MediaSession API は保護されたコンテキストでしか動かない。

## 4. 確認すること

順番に見ていく。**3 番目が本題**。

1. **検索して曲が出るか**
   - 出なければ node サーバーが動いていないか、Tailscale の経路の問題
2. **曲をタップして音が鳴るか**
   - 最初のタップで再生許可を取る仕組みが入っている（`audio-engine.ts` の `unlock`）
3. **画面をロックしても鳴り続けるか** ← 最重要
   - ロック画面に曲名・アーティスト・再生ボタンが出るか
   - ロック画面の再生 / 一時停止 / 次へ が効くか
   - シークバーが動くか
4. **曲が終わったとき、ロックしたまま次の曲へ進むか**
   - iOS の PWA で報告のある弱点。ここが駄目なら連続再生が成立しない
5. **ホーム画面に追加した場合も同じか**
   - 共有 → ホーム画面に追加 → そこから起動
   - **Safari のタブでは動くのにホーム画面から起動すると止まる、という報告があるので、必ず両方試す**
6. **他のアプリに切り替えても鳴り続けるか**

## 5. 結果の見かた

- **3 と 4 が通れば構成は成立する。** 残りは実装を進めるだけ
- **3 が駄目なら PWA では無理。** ネイティブアプリに切り替えるか、プロジェクトを畳むかの判断になる
- **3 は通るが 4 が駄目な場合**、曲の終わりを待たずに次を先読みして繋ぐ回避策を試す余地がある

## うまくいかないときに見るところ

- **音が鳴らない** — Safari の設定でメディアの自動再生が制限されていないか。画面を一度タップしてから曲を選ぶ
- **検索が空** — `curl https://<ホスト>:8443/node-api/api/health` が通るか確認する
- **繋がらない** — iPhone の Tailscale が有効か、同じ tailnet か
- **音が途切れる** — 自宅の上り帯域か、node の取得処理が詰まっている可能性

---

## 現在の到達点 (2026-07-27)

macOS の Chromium で以下まで確認済み:

- 検索 → 再生が実際に動作
- `currentTime` が進行、`duration` を正しく取得
- MediaSession に曲名と再生状態が入る
- Tailscale の HTTPS 経由で、画面・API・音声 (206 応答) すべて到達

**iOS 実機での確認はこれから。**
