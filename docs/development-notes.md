# 開発上の注意

README から移した、コードを触る人向けのメモ。設計の背景は [decisions.md](decisions.md) を参照。

## 触る前に知っておくこと

- **中央サーバー (hub) に音声のバイト列を通さない。** ここを守る限り、帯域は利用者が増えてもほとんど増えず、著作物を保持も中継もしていない状態を保てる。この前提を崩す変更は、コスト構造と法的な立ち位置の両方を同時に壊す
- **解決処理は壊れる前提で作る。** 供給元の仕様変更で全ユーザーが同時に再生できなくなる事故は、法的な問題より遥かに高い確率で起きる。壊れたときは必ず理由を表示し、ダウンロード済みのみ再生する縮退動作へ落とす（`resolver.ts` の `summarize` が入口）
- **PWA から外部 URL を直接叩かない。** 内蔵サーバー (node) が中継することで CORS と Range を自前で扱える。ジャケット画像も同様（PC 未接続時は hub が中継する）
- **開発中の中継（`/node-api`, `/hub-api`）を外さない。** スマートフォンからは HTTPS で入ってくるため、HTTP の node を直接叩くと混在コンテンツで弾かれる

## 各ユーザーの PC (node) について

- **各ユーザー自身の回線から、自分のために取得する**のがこの構成の要。中央が代わりに取得する構成にすると、供給元から見て 1 つの IP に集中し、bot 判定で止まる。分散しているからこそ動く
- ウィンドウを閉じてもサーバーは止めない。落とすと外出先のスマートフォンから DL 済みの曲しか鳴らせなくなる
- 供給元の URL をそのまま中継しない。単発で全部読みにいくと極端に絞られる（実測 30KB/s 前後）。一度手元に落としきってから配る

## 同時リスニング

- ズレの吸収は 2 段階。わずかなら playbackRate で滑らかに詰め、大きく外れたときだけシークする（`SYNC_DRIFT_NUDGE_MS` / `SYNC_DRIFT_SEEK_MS`）。毎秒シークすると再生が壊れる
- 参加者ごとに取得の成否が変わりうるので、「誰がまだ準備できていないか」を必ず UI に出す。黙って一人だけ無音になるのが最悪の壊れ方

## 運営方針（設計と一体のもの）

- 無料・非営利で運営する。営利性は責任論で最も不利に働く
- 供給元のサービス名を、名称・宣伝・UI・ドメインのどこにも出さない
- 「広告なし」を訴求にしない。訴求は共有と同時リスニングに一本化する
- 自宅で運用する場合、グローバル IP を露出させない（Cloudflare Tunnel 等を挟む）

## ビルドの注意

- `rtk pnpm typecheck` は型エラーを握りつぶすことがある。型検査は素の `pnpm --filter "./packages/*" typecheck` を使う
- 配布物は必ず `pnpm run dist:mac` / `dist:win` で組む。`electron-builder` を直接呼ぶと古い dist を包む
- `dist:*` の後は `prepare:dev` が走り、ネイティブモジュールを手元の形に戻す（universal / Windows 用のままだと次の起動で落ちる）

## 動作確認の足場

- 開発中はスマートフォンから Tailscale 経由でも動かせる（[ios-testing.md](ios-testing.md)）。これは開発の足場で、利用者に求めるものではない
- ユーザーストーリーと検証状態は [user-stories.csv](user-stories.csv) で管理している
